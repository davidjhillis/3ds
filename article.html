Building Edit Checks in Rave EDC

Updated Jun 12, 2026 6 min read Applies to Rave EDC 2026.3

Edit checks enforce the data-validation rules in your study, flagging values that fall outside expected ranges or violate protocol logic so that sites can correct them at the point of entry.

Overview

An edit check evaluates one or more fields on an eCRF and, when its condition is met, raises a query or takes another configured action. Edit checks are defined in the study design and take effect once the design is pushed to production.

Design vs. production

Edit checks you add or change apply only after the study design is migrated to the production environment. Test thoroughly in your sandbox first.

Before you begin

  • You have the Study Designer role for the study.
  • The target fields already exist on the relevant forms.
  • You know which action the check should take — raise a query, mark non-conformant, or open a form.

Create an edit check

  1. Open Architect and select your study, then choose Edit Checks.
  2. Select Add Edit Check and give it a clear, unique name.
  3. Add one or more check steps defining the fields and the condition to evaluate.
  4. Add the check action — for example, open a query with your query text.
  5. Save, then validate the check against test data before migrating.

Tip

Name checks by field and intent (e.g., SYSBP_RANGE_HIGH) so they are easy to find and audit later.

Edit check types

TypePurposeExample
RangeValue must fall within expected limitsSystolic BP between 60 and 250 mmHg
RequiredA field must be completedVisit date is not blank
ConsistencyTwo or more fields must agreeEnd date is on or after start date
FormatValue matches an expected patternLab units match the reference set
ProtocolFlags a protocol deviationDose exceeds the protocol maximum

Example: range check

A simple range check on a systolic blood-pressure field that opens a query when the value is outside the expected window:

# Edit check: SYSBP_RANGE_HIGH
WHEN SYSBP IS NOT NULL AND ( SYSBP < 60 OR SYSBP > 250 )
THEN OPEN QUERY "Systolic BP is outside the expected range (60–250 mmHg). Please verify."

Test your edit checks

Enter representative values in the sandbox — including boundary and out-of-range cases — and confirm each check fires exactly when expected and stays silent otherwise. Review the query text as the site will see it.

Best practices

  • Keep each check focused on a single rule for easier maintenance.
  • Write query text that tells the site exactly what to do.
  • Avoid over-checking — too many queries slow data entry and frustrate sites.
  • Document the intent of complex checks for future study builders.
